# 献立プランナー設計スキル

献立づくりは「おいしそうなレシピを並べる」作業ではなく、**栄養・食材の使い切り・買い物の手間・飽き**という
4つの制約を同時に満たす組合せ最適化に近い。人間はこの4つを同時に見られないので破綻する
(=買った白菜が半分腐る、3日連続で鶏肉、塩分が基準の2倍)。ここでの仕事は、その4つを
明示的な数値と手順に落として、破綻しない案を出すこと。

## 中核となる考え方

**1食単位ではなく「日」と「週」で評価する。**
1食の栄養を完璧にしようとすると献立は不自然になる(朝からブロッコリーと鶏胸肉)。
人間の食生活は1日〜1週間で均されるので、判定も1日合計・週平均で行う。
朝が軽いなら夕食で補う、という当たり前の調整ができるようになる。

**食材は「買う単位」で考える。**
レシピが要求するのは「にんじん 40g」でも、店で売っているのは1本(150g)。
この差を無視するとレシピ通りに買って必ず余る。余りは次の献立で消費先を確保する。
これが献立と買い物リストを別々に作ってはいけない理由。

**献立は確定した予定ではなく、書き換え前提の下書き。**
90日先の予定は必ず変わる。だから「直近だけ差し替えても、その先と買い物リストが壊れない」
構造にしておく。冷蔵庫の在庫入力による再生成は例外処理ではなく、通常運転。

## 手順

### 1. 目標値を決める

利用者の人数・年齢・性別・活動量から1日あたりの目標を出す。日本人の食事摂取基準の考え方に沿う。
根拠となる数値と判定しきい値は `references/nutrition.md` にまとめてあるので、
栄養計算・判定を書く前にそれを読むこと。暗記の数値で書くと食塩やたんぱく質の桁を外しやすい。

### 2. 献立を生成する

1日を朝食・昼食・夕食に分け、夕食は「主菜+副菜+汁物+主食」の組で扱う。
候補レシピをスコアで並べて上位から選ぶ。スコアに入れる要素と、それぞれが何を防いでいるか:

| 要素 | 何を防ぐか |
|---|---|
| 不足栄養素の充足度 | その日ここまでの不足(たんぱく質・食物繊維・鉄・カルシウム等)を埋める候補を優遇 |
| 主材料の連続 | 「昨日も鶏」を防ぐ。肉/魚/卵/大豆/その他の系統を直近数日で分散させる |
| 同一レシピの再登場 | 最低でも2〜3週間は同じものを出さない |
| 調理時間 | 平日夜は短時間、週末は手間のかかるものを許す |
| 季節 | 旬の食材を優遇。冬にトマトサラダを並べない |
| 在庫の消費 | 冷蔵庫にある食材、特に期限が近いものを使うレシピを強く優遇 |
| 調理法の重複 | 揚げ物が2日続く、全部炒め物、を避ける |

**ランダム性は必ず入れる。ただし再現可能に。**
最高スコアだけを選ぶと毎回同じ献立になり「自動で決めてくれる」価値が消える。
上位数件から重み付き抽選する。ただしシード付き乱数を使い、同じ条件なら同じ結果が出るようにする
(利用者が「さっきの献立に戻して」と言えるように)。

### 3. 栄養を判定する

生成後に1日ごと・週ごとに検算し、目標から外れた日を**具体的に指摘する**。
「バランスが良いです」ではなく「木曜は食物繊維が目標の62%、副菜をひじきの煮物に替えると充足」まで書く。
判定が指摘で終わると利用者は動けないので、必ず差し替え候補まで出す。

### 4. 買い物リストに集約する

買い物日(週1〜2回)を決め、次の買い物日までのレシピが必要とする食材を合算する。ここで:

- **生鮮は日持ちで区切る**。買い物日から日持ち日数を超えて使うぶんは、その回では買わない
- **購入単位に丸める**。「にんじん 210g」→「にんじん 2本」。丸めて出た余りは翌週の献立で消費先を確保する
- **売り場順に並べる**。青果 → 精肉 → 鮮魚 → 乳卵 → 豆腐練物 → 調味料 → 乾物 → 冷凍。店内を往復させない
- **在庫を差し引く**。冷蔵庫にあるものを買わせない

### 5. 冷蔵庫の在庫から差し替える

在庫入力があったら、**直近数日(既定7日)だけ**を再生成する。全期間を作り直さないのは、
先の予定と買い物リストが毎回変わると利用者が計画を立てられなくなるため。
期限が近い食材ほど早い日に割り当てる。差し替えたら「何が何に変わったか」と
「この在庫は何日の何で使い切る」を提示する。使い切れない在庫があるなら正直に言う。

## 提示の仕方

献立を出すときは、必ずこの3点をセットにする。どれが欠けても利用者は動けない:

1. **いつ何を食べるか**(日付・食事区分・料理名)
2. **いつ何を買うか**(買い物日・売り場別・数量)
3. **なぜそうなっているか**(栄養の判定結果、在庫の消費計画)

数値は丸めて出す。「たんぱく質 68.4231g」ではなく「たんぱく質 68g(目標60g / 114%)」。
利用者が見るのは達成率であって小数第4位ではない。

## 実装時の注意

- 栄養値はレシピに直接書かず、**食材マスタ(100gあたり)× 使用量から計算する**。
  レシピごとに手で栄養値を書くと必ず矛盾し、材料を変えたときに更新漏れが起きる
- 分量は1人前で持ち、人数倍は表示・集計時に掛ける
- 生成は決定論的に(シード固定)。テストが書けなくなるので `Math.random()` を直接使わない
